## Project Overview

CurtainBot MARK2 is an ESP32-based automatic curtain controller written in Arduino C++. It controls two motorized curtains via an L298N motor driver with quadrature encoder feedback, integrates with Arduino IoT Cloud for remote control, and supports scheduled open/close routines.

## Build & Upload

This is an Arduino project — there are no traditional build scripts. Compile and upload via:
- **Arduino IDE**: Open `firmware/curtainbot2_nov19a/curtainbot2_nov19a.ino`, select board `ESP32 DoiT DevKit V1`, and upload.
- **Arduino CLI**: `arduino-cli compile --fqbn esp32:esp32:esp32doit-devkit-v1 firmware/curtainbot2_nov19a && arduino-cli upload -p <PORT> --fqbn esp32:esp32:esp32doit-devkit-v1 firmware/curtainbot2_nov19a`
- **Serial monitor baud rate**: 115200

Before building, copy `firmware/curtainbot2_nov19a/arduino_secrets.h.template` to `firmware/curtainbot2_nov19a/arduino_secrets.h` and fill in `SECRET_SSID`, `SECRET_OPTIONAL_PASS`, and `SECRET_DEVICE_KEY`.

## Architecture

### Active Sketch: `firmware/curtainbot2_nov19a/`

**`curtainbot2_nov19a.ino`** — Main sketch. Owns the `setup()`/`loop()` cycle. Responsibilities:
- Initializes `ArduinoCloud` and syncs cloud properties from `thingProperties.h`
- Calls `controlLoop()` (from `control.h`) each iteration for motor/button handling
- Checks current time against `morning_time`/`night_time` to trigger automated open/close
- Parses commands arriving via the `stat_Messages` cloud string variable (`H`, `I`, `M<HH:MM>`, `N<HH:MM>`, `Ms`/`Mr`/`Ns`/`Nr`)
- Updates `left_Curtain_Status` and `right_Curtain_Status` cloud strings as motor states change

**`control.h`** — Self-contained motor control library. Key elements:
- `Motor` class: manages a single motor with PWM speed, direction, acceleration ramping, encoder stall detection, button debouncing, and LED feedback
- Two global instances: `motor1` (left curtain, GPIO 16/17/5) and `motor2` (right curtain, GPIO 18/19/4)
- Encoder ISRs (`IRAM_ATTR encoderISR1/2`) track quadrature counts in `encCount1`/`encCount2`
- `controlLoop()` — called from main loop; runs `motor1.update()` and `motor2.update()`
- `Motor::update()` handles: button press detection → state transitions, ramp PWM, stall detection (encoder stops changing while motor commanded), limit locking

**`thingProperties.h`** — Auto-generated by Arduino IoT Cloud. Defines cloud properties and their change callbacks. Do not edit manually; regenerate via the IoT Cloud dashboard.

**`legacy/controlCode/controlCode.ino`** — Legacy standalone sketch (no cloud). Useful as a reference for pure local button-and-encoder motor control without IoT overhead.

**`firmware/curtainbot2_nov19a/webServer/webServer.ino`** — Experimental; not integrated with the main sketch.

### Motor State Machine

```
STOPPED ──open cmd──> MOVING_OPEN  ──stall detected──> OPEN
STOPPED ──close cmd─> MOVING_CLOSED──stall detected──> CLOSED
OPEN / CLOSED ──opposite cmd──> MOVING_* (ramps up)
```

Stall detection: if `encCount` does not change for `STALL_TIMEOUT` ms while the motor is commanded, the motor is considered at its limit and transitions to OPEN or CLOSED.

### Pin Map

| Signal | GPIO |
|--------|------|
| Motor1 IN1/IN2/EN | 16, 17, 5 |
| Motor2 IN1/IN2/EN | 18, 19, 4 |
| Encoder1 A/B | 32, 33 |
| Encoder2 A/B | 25, 26 |
| Button1 / Button2 | 21, 22 |
| LED1 / LED2 | 23, 27 |
| Connection LED | 2 |

### Cloud Command Reference

Commands are sent by writing to the `stat_Messages` cloud string:

| Command | Action |
|---------|--------|
| `H` | Print help menu |
| `I` | Print current schedule info |
| `MHH:MM` | Set morning open time |
| `Ms` / `Mr` | Pause / resume morning routine |
| `NHH:MM` | Set night close time |
| `Ns` / `Nr` | Pause / resume night routine |
